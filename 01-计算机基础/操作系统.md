# 一、系统结构

## (一) CPU 高速缓存

- Cache：L1 缓存分为指令缓存、数据缓存，L2 CPU 核心 独占，L3 共享。

### 1. Cache 与内存一致性

- **写直达 (Write Through)**：每次写操作都将数据同时写入 Cache 和内存。
- **写回 (Write Back)**：每次写操作只将数据写入 Cache，等到修改过 Cache Line 被替换时才写入到内存。

### 2. 缓存一致性问题

- 因为 L1 和 L2 Cache 是核心独有的，一个核心修改了缓存中某个数据，但是没有将数据写回，其他核心读取内存中的数据时就会导致读取数据不一致。
- 解决缓存一致性的两个原则

- **写传播**：某个 CPU 核心里的 Cache 数据更新时，必须要传播到其他核心的 Cache。
- **事务的串行化**：某个 CPU 核心里对数据的操作顺序，必须在其他核心看起来顺序是一样的。

### 3. 总线嗅探

- 某个核心修改了 Cache 中的数据后，通过总线把事件广播给其他所有核心。所有核心都要监听总线上的广播事件，并检查自己的 Cache 中是否有该数据，如果有则需要更新。
- 缺点：总线嗅探会加重总线和 CPU 的负载，并且无法实现事务串行化。

### 4. MESI 协议

- MESI 协议将缓存行分为 4 个状态：**修改 Modified、独占 Exclusive、共享 Shared、失效 Invalid**。
- 对于 **Modified**、**Exclusive** 状态的数据，CPU 在修改他们时不需要发送总线广播。
- CPU 核心在读数据时，会发送**总线读请求**，如果有其他 CPU 修改或独占该数据，就会将状态修改为共享，并将最新数据发送给当前核心。

![[MESI 协议.webp]]

### 5. 伪共享问题

- 多个线程同时读写同一个 Cache Line 的不同变量，导致 CPU Cache 失效的现象称为**伪共享**。
- 可以通过对齐填充的方式，让一个缓存行只保存一个共享变量，相邻的共享变量保存在不同的缓存行中，即空间换时间。

## (二) 内核态和用户态

- **特权指令：**只能由操作系统内核态执行的指令，如：内存指令、时钟指令、IO 指令。

### 1. 什么时候会发生模式切换

- 程序主动发起**系统调用**
- 程序被动**中断**（中断来自处理器外部）
- 程序出现错误即**异常**（异常来自于处理器执行指令）：缺页异常、除零异常

# 二、进程管理

## (一) 进程是什么

- 进程是运行中的程序，是操作系统分配资源和调度的基本单位。
- 引入进程是为了更好地实现多道程序并发执行，提高资源利用率和系统吞吐量。

### 1. 进程控制块

- 进程控制块 **PCB** 是进程实体的一部分，是进程存在的**唯一标志**。
- 进程描述信息：**进程标识符 PID**、**用户标识符 UID**（属于哪个用户）。
- 进程控制和管理信息：进程**状态**、进程**优先级**、代码入口、**信号量**使用等。
- 资源分配清单：内存地址空间和虚拟地址空间的信息、打开的**文件描述符**、外部设备等
- 处理机相关信息：各种**寄存器**值、**状态字**等。

### 2. 进程控制

- 进程**创建**：创建 PCB、向 PCB 中写入信息、分配必要资源，最后设置为就绪态并插入就绪队列。子进程可以继承父进程的资源，子进程终止时归还资源。
- 进程**终止**：释放 CPU、终止子孙进程、归还资源 (给父进程或操作系统)、删除 PCB。
- 进程**阻塞**：进程因为请求资源失败、等待 IO 完成、等待数据到达等，进程转变为阻塞态并插入等待队列。
- 进程**唤醒**：当进程期待的事件出现，由相关进程调用唤醒原语唤醒，状态转变为就绪态并插入就绪队列。

### 3. 进程的状态及转换

![[进程五个状态.webp]]

- 创建态：内核正在执行创建进程的步骤。
- 终止态：内核正在执行终止进程的步骤。

### 4. 进程的上下文切换

- **CPU 上下文**：寄存器、程序计数器 PC。
- 进程是由内核管理和调度的，所以进程的切换只能发生在**内核态**。进程的上下文保存在 **PCB** 中，因此发生上下文切换时，就需要将寄存器的值、进程状态、内存信息等保存在 PCB 中，然后加载新进程的 PCB 中的上下文信息。

### 5. 进程间通信

1. **管道**

- 只能**单向通信**，先进先出，一端写入另一端读出，效率低。**匿名管道**只能实现父子、兄弟进程通信；**命名管道**本质是一个文件，可以实现无关进程通信。

2. **消息队列**

- 由**内核**维护的消息缓冲区，消息体是由发送方和接收方事先约定好数据结构。
- 消息队列**不适合大数据**的传输，且存在用户态与内核态之间的**数据拷贝开销**。

3. **共享内存**

- 将不同的进程的一部分**虚拟地址映射到相同的物理内存**。
- 如果多个进程同时修改同一个共享内存，就会导致冲突。

4. **信号量**

- 用来防止多进程竞争共享资源，可以实现进程间的互斥与同步。
- P 操作：减 1，如果>=0，则继续执行；如果<0，则阻塞等待。
- V 操作：加 1，如果<=0，则唤醒一个进程。
- 互斥信号量初始为 1，先 P 后 V；同步信号量初始为 0，先 V 后 P。

5. **信号**

- 异步通信机制。给进程发送信号时，进程可以选择执行默认操作、捕获信号并执行信号处理函数、忽略信号。

6. **Sokcet**

## (二) 线程是什么

- 引入线程为了减少程序并发执行时的**时空开销**，进一步提供系统的并发性能。
- 线程是轻量级进程，是进程的一部分，由**线程 ID、PC、寄存器、堆栈**组成。线程是处理器调度和分配的基本单位，共享进程资源。

### 1. 线程和进程之间的区别

- 进程是操作系统分配资源的基本单位，线程 CPU 调度的基本单位，线程只拥有必不可少的资源（栈、寄存器）。
- 线程的时空开销比进程小得多。

- 进程创建或终止时，需要进行内存、文件等资源的管理，但是线程只需要共享并使用这些资源，而不负责管理。
- 线程切换的上下文开销只涉及寄存器、栈等，比进程小得多。
- 线程共享进程的地址空间，因此线程之间的同步和通信更容易。

### 2. 线程的实现方式

1. 用户级线程：在用户空间实现的线程，线程的管理与调度都在用户态完成。对操作系统来说，看不见线程，调度也是以进程为单位。进行系统调用时，会导致进程中的线程全都阻塞。
2. 内核级线程：由内核管理的线程，线程调度和管理都在内核态完成。进行线程切换时会发生模式切换。一个线程发起系统调用不会阻塞所有线程。

### 3. 线程控制块与上下文切换

- 线程控制块 **TCB** 包括：线程描述符 TID、寄存器、线程状态、线程优先级、线程用来保存上下文的独占内存、堆栈指针。
- 当切换的线程不属于同一个进程时，线程上下文切换就等于进程上下文切换；如果是同一个进程，只用保存 TCB 中的内容。

### 4. 线程间通信

- 互斥锁
- 条件变量
- 读写锁
- 信号量
- 原子变量
- 无锁队列
- 管道/消息队列

## (三) 进程调度

### 1. 调度目标

- CPU 利用率 = CPU 工作时间 /（CPU 工作时间+CPU 空闲时间）
- 系统吞吐量 = 单位时间内 CPU 完成任务的数量。所以短作业优先。
- 周转时间 = 作业完成时间 - 作业提交时间。包含作业等待调度、排队、任务执行的时间。
- 等待时间 = 进程在就绪队列中等待时间。
- 响应时间 = 用户提交请求到系统产生响应的时间。

### 2. 调度算法

1. **先来先服务**
2. **短作业优先**（SJF）：预估运行时间最短的作业优先。

- 平均等待时间、平均周转时间最短

3. **优先级调度**
4. **时间片轮转**（Round Robin，RR）：将就绪进程按 FCFS 排队，然后每隔一个时间片产生一次时钟中断，并由时钟中断处理程序激活调度程序。
5. **多级反馈队列**（Multi-Level FeedBack Queue，MLFQ）

- 设置多个就绪队列，每个队列优先级不同，优先级越高的队列中的进程分配的时间片越短。
- 进程如果用完时间片还没有结束，则降级到下一级队列的末尾。高优先级队列处理完，才会处理低优先级队列。
- 短作业优先，长作业也能得到部分执行。

6. **完全公平调度**（CompletelyFairScheduler， CFS）

- 基于虚拟运行时间（vruntime）分配 cpu，所有进程按照权重公平获得执行时间，用红黑树选择最小 vruntime 的进程。

# 三、内存管理

- 逻辑地址/虚拟地址：从 0 开始编址的地址。虚拟内存大小由虚拟地址位数决定即 2^n-1。

## (一) 内存分段

- 分段管理是逻辑划分，将逻辑地址空间划分为大小不同的段，分段地址空间是**二维**的。
- 分段的**逻辑地址**包括：段号 + 段内偏移量。
- **段表项** = 段号 + 段基地址 + 段长。
- **段表寄存器**中存储了段表起始地址、段表长度。每次查询时，首先判断段号是否超出段表长度，然后找到段表项，再判断段内偏移量是否越界，最后加上段基地址得到物理地址。

## (二) 内存分页

- 将内存空间分为大小固定的分区，称为**页帧**。将逻辑地址分为同样大小的区域，称为**页面**。
- 页面不能过小，这会导致页面数过多；页面也不能过大，会导致业内碎片增多，降低内存利用率。
- 分页的**逻辑地址** = 页号 + 页内偏移量。
- **页表项** = 页号 + 块号。每个进程有自己独立的页表
- **页表寄存器**中存储页表基地址、页表长度。每次查询时，判断页号是否越界，如果越界则产生越界中断，否则用**物理块号*页面大小+页内偏移**得到物理地址。

### 1. 快表 TLB

- 如果页表全部放在内存中，取一次数据需要**两次访存**：一次访问页表、一次读取数据。
- 快表 TLB 是一个具有**并行查找**能力的高速缓冲器，存储当前访问的若干页表项，用来加速地址变换的过程。
- 在有快表的情况下，查询数据时，首先用页号查找 TLB，如果命中了，就直接去内存中查找数据，只需要**一次访存**。如果没有命中，则再查询页表。

### 2. 多级页表

- 在 32 位系统上，对常用的 4KB 大小的页面，也需要 2^20 个页，导致页表本身占用内存过大。
- 采用多级页表，将逻辑地址划分为页目录号+页号+页内偏移。

## (三) 虚拟内存

- 程序运行时只加载少数当前要用到的页面，在执行过程中，再将不在内存中的数据加载到内存中，即**请求调页**。当内存不足时，操作系统会将暂时用不到的页面换到外存，然后调入需要的数据，即**页面置换**。这样操作系统就好像提供了一个比实际内存大得多的内存，即**虚拟内存**。

## (四) 内存映射文件 mmap

- 内存映射文件 mmap 是操作系统向应用程序提供的一个系统调用，它将磁盘文件映射到进程的虚拟地址的某个区域，然后用访问内存的方式读写文件。
- 在进行映射时，不会读入实际的内容，只有真正访问页面时才会将页面读入内存。当进程退出或者关闭文件映射时，才将脏页写回磁盘。

# 四、IO

## (一) 缓冲与非缓冲 I/O

- **缓冲 I/O**：利用的标准库的缓存实现文件的加速访问，而标准库通过系统调用访问文件。
- **非缓冲 I/O**：直接通过系统调用访问文件，不经过标准库缓存。

## (二) 直接与非直接 I/O

- Linux 内核为了减少磁盘 I/O 次数，在系统调用后，会把用户数据拷贝到内核中的 Page Cache 缓存起来，只有当缓存满足某些条件的时候，才发起磁盘 I/O 的请求。
- **直接 I/O**：不会发生内核缓存和用户程序之间数据复制，而是直接经过文件系统访问磁盘。
- **非直接 I/O**：读操作时，从内核缓存中读取数据；写操作时，数据从用户程序拷贝给内核缓存，再由内核决定什么时候写入数据到磁盘。

- 调用 `write` 时，内核缓存的数据过多。
- 调用 `sync`，会将缓存刷新到磁盘。
- 内存不足，无法再分配页面时。

## (三) 同步与异步 I/O

### 1. 同步阻塞 I/O

- 用户程序执行 `read`，线程会被阻塞，一直等到内核数据准备好后，将数据从内核缓冲区拷贝到应用程序的缓冲区中，当拷贝过程完成，read 才会返回。

### 2. 同步非阻塞 I/O

- 用户程序反复调用非阻塞 `read`轮询内核是否准备好数据，直到最后一次内核准备好数据，就将数据拷贝到程序的缓冲区。

### 3. 异步 IO

- 用户程序调用`aio_read`后立即返回，内核自动准备数据、自动将数据拷贝到用户空间，拷贝完成后通知用户程序处理数据。

## (四) IO 多路复用

### 1. select（2 次拷贝、2 次遍历、个数有限 1024）

- select 会将所有需要监视的文件描述符 fd 放到一个集合中，然后 select 系统调用会将 fd 集合拷贝到内核中。然后内核轮询所有 fd，如果有事件发生，将该 fd 标记为就绪，再将 fd 集合复制到用户空间。程序再次轮询找到就绪的 fd 并处理。

### 2. poll（2 次拷贝、2 次遍历、个数不限）

- poll 采用结构体数组，基于链表组织 fd，没有个数限制。但是同样需要在用户态和内核态之间来回复制和轮询。

### 3. epoll（1 次拷贝、只遍历就绪事件、个数不限）

- epoll 在内核中使用**红黑树**保存进程中所有待检测的文件描述符 fd，所有需要监控的 fd 通过 `**epoll_ctl()**` 加入红黑树中。
- epoll 使用**事件驱动**机制，内核中维护了一个**链表**记录**就绪事件**。当事件发生时，内核通过回调函数将该事件插入就绪事件链表，程序调用 `**epoll_wait()**` 时返回有事件发生的 fd 的个数。然后将当前事件和数据拷贝到用户空间。

## (五) 零拷贝

### 1. DMA 直接内存访问

- 用户发起 IO 请求后，os 会将请求交给 DMA 控制器，由 DMA 负责调用磁盘将数据读取到磁盘缓冲区，然后再拷贝到内核缓冲区，最后通过 IO 中断通知 CPU，最后再将数据拷贝到用户空间。

### 2. 网络传输的零拷贝

1. **mmap + write**（3 次拷贝、4 次模式切换）

- 通过 mmap 系统调用，DMA 将数据拷贝到内核缓冲区，然后将内核缓冲区中的数据映射到用户空间，减少一次拷贝。
- 然后 write 将内核缓冲区中的数据拷贝到 socket 缓冲区，最后 DMA 拷贝数据到网卡缓冲区。

2. **sendfile**（3 次拷贝、2 次模式切换）

- DMA：磁盘->内核缓冲区。
- CPU：内核缓冲区-> socket 缓冲区。
- DMA：socket 缓冲区->网卡缓冲区。

3. **SG-DMA**（2 次拷贝、2 次模式切换）

- 如果网卡支持 **SG-DMA**，则 **sendfile** 系统调用只需要 2 次拷贝、2 次模式切换。
- DMA：磁盘->内核缓冲区。
- SG-DMA：内核缓冲区->网卡缓冲区。
