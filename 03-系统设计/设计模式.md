# 一、软件开发设计原则

1. **单一职责原则 (Single Responsibility Principle, SRP)**

- 一个类或模块只有一个发生变化的原因。
- 一个类只承担一个职责。如果一个类承担多个职责，当其中一个职责发生变化，就会影响到其他职责的代码实现，增加代码的复杂性和耦合度。

2. **开闭原则 (Open-Closed Principle, OCP)**

- 一个类、模块、函数对扩展开放，对修改关闭。
- 需要新增功能时，应该通过新增代码实现功能。而不是修改已有的、工作良好的代码。

3. **里氏替换原则 (Liskov Substitution Principle, LSP)**

- 所有引用基类的地方可以必须能够直接替换为其子类。
- 子类应该可以完全替代父类，且程序不会发生错误或异常。也就是说，子类继承父类时，不应该改变父类预期的行为，子类的行为应该包含父类的行为。

4. **迪米特法则/最少知识原则**

- 两个实体之间如果不需要直接通信，就不应该发生直接的相互调用，可以通过第三方转发调用。降低类之间的耦合度。

5. **接口隔离原则 (Interface Segregation Principle, ISP)**

- 类不应该依赖它不需要的接口，即类之间关系应该建立在最小的依赖上。
- 接口的设计要专即职责要清晰单一，根据不同的功能设计多个细粒度的接口，而不是一个接口多个功能。

6. **依赖倒置原则**

- 上层模块应该依赖于底层的抽象接口，而不是具体的底层实现。抽象不依赖于细节，细节应该依赖于抽象。
- 模块之间的依赖应该建立在抽象/接口上，而不能依赖于具体的实现。

# 二、创建型模式

- 关注对象的创建过程。

## (一) 工厂模式

### 1. 简单工厂

- 有一个独立的工厂类创建对象，客户端不需要关注创建逻辑，只需要提供创建的参数。

### 2. 静态工厂

- 基于产品类的静态方法创建对象。

### 3. 抽象工厂

- 用一个接口/抽象类定义创建不同产品的方法，实现不同的工厂类，具体的工厂类的实现不同的创建对象的逻辑。

## (二) 线程安全的单例模式

### 1. 普通单例

- **饿汉式**：类加载时就创建该单例对象。

```
public final class Singleton implements Serializable {
    private Singleton() {}
    // 静态成员变量的初始化是在类加载阶段，可以保证线程安全。
    private static final Singleton INSTANCE = new Singleton();
    
    public static Singleton getInstance() {
        return INSTANCE;
    }
    
    public Object readResolve() {	// 防止反序列化破坏单例。
        return INSTANCE;
    }
}
```

- **懒汉式**：类加载时不创建单例对象，首次使用时才创建。

### 2. 同步方法 => 懒汉式静态单例

```
public final class Singleton {
    private static Singleton INSTANCE = null;
    
    private Singleton() { }
    
    public synchronized static Singleton getInstance() {
        if (INSTANCE == null) {
            INSTANCE = new Singleton();
        }
        return INSTANCE;
    }
}
```

### 3. 双重检验锁 + 犹豫模式 => 懒汉式静态单例

```
public final class Singleton {
    private static volatile Singleton INSTANCE;
    
    private Singleton() { }
    
    public static Singleton getInstance() {
        if (INSTANCE == null) {
            synchronized (Singleton.class) {
                if (INSTANCE == null) {
                    INSTANCE = new Singleton();
                }
            }
        }
        return INSTANCE;
    }
}
```

### 4. 枚举单例

- 枚举对象就是枚举类的静态成员变量，可以保证线程安全。
- 枚举单例不会被反射、反序列化破坏单例。

```
enum Singleton { 
    INSTANCE; 
}
```

### 5. 静态内部类

- 静态内部类可以实现懒加载，因为 JVM 只有在使用类的时候才会对类进行初始化。

```
public final class Singleton {
    private Singleton() { }
    
    private static class SingletonHolder {
        static final Singleton INSTANCE = new Singleton();
    }
    // 没有并发问题
    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
```

# 三、结构型模式

- 关注类和对象的组合，形成高效的接口，实现复杂功能。

## (一) 享元模式

- 重用数量有限的同一类对象。

### 1. 包装类

- 包装类中都有相应的**静态内部类**，静态内部类加载通过类初始化代码块 (static 代码块)，创建并保存了一些实例，后续如果使用到范围内的包装类可以直接复用。
- 手动调用 `valueOf()`或者触发自动装箱时，没有超出缓存范围时都会重用缓存中的实例。只有超出范围或者`new`才会创建新对象。
- Byte、Short、Integer、Long 缓存值在 `-128~127` 范围的对象。
- Character 缓存值在`0~127`范围内的对象。
- Boolean 缓存了`TRUE`、`FALSE`。

### 3. 线程池

- 核心在于线程复用和资源控制，防止频繁地创建和销毁线程带来的开销，同时可以控制系统中线程数量不会无线膨胀。

## (三) 装饰器模式

- 动态地给一个对象增加一些额外的功能或特性，但是又不改变他的接口，相比于继承更加灵活。

### 1. 使用场景

1. 只想扩展一个对象，但是不影响其他对象。
2. 不适合或无法使用继承的情况。

## (四) 适配器模式

- 将一个接口转换为客户端需要的另一种接口，使得原本因为接口不兼容不能一起工作的类可以一起工作。

### 1. 使用场景

- 使用适配器复用已存在的类。
- 将不同的接口统一成同一个接口，消除接口之间的差异。

### 2. 实现

1. 类继承

- 适配器类同时继承被适配类和目标接口。耦合度高。

2. 组合/关联

- 适配器类实现目标接口，并持有被适配类的对象。

# 四、行为类模式

## (一) 策略模式

- 定义一系列算法（策略），将每个算法封装起来，并使它们可以相互替换。
- 使用者只需要调用抽象的策略接口，而不用管具体的策略实现。

### 1. 例子

- 线程池拒绝策略。
- 支付策略。

## (二) 模板方法模式

## (三) 责任链模式

- 将多个处理器编排成一个链，将请求在链上传递，每个处理器判断是否能处理。一般分为两种场景：请求需要能被所有处理器处理，如果有任何一个不能就会报错；请求只要能被其中一些处理器处理，就可以输出结果。

### 1. 使用场景

- 过滤器：每个过滤器处理一种逻辑，并决定是否可以放行到下一个过滤器或返回拒绝信息。
- 流水线：链式处理一个对象，每个处理器可能处理也可能直接返回原对象。
