## (三) 上下文窗口

- 上下文窗口是大模型一次能处理的 Token 上限，一般包含**系统提示词、用户提示词、历史对话、RAG 检索内容、工具调用 Schema** 等。

## (四) 上下文工程（Context Engineering）

- **系统上下文**：Role、Task、约束（禁止项、优先级、风格、长度等）、输入、输出规范。
- **用户与检索上下文**：短期记忆与长期记忆、混合检索 + 重排序。
- **查询问题重写**：对用户的提问进行重写，消除歧义。
- **Lost in the Middle 现象**：大模型更容易忽略中间的内容，对 Prompt 开头和结尾的内容更敏感。

## (五) 幻觉

- **事实性幻觉**：篡改或捏造不存在的事实。
- **逻辑性幻觉**：比如自相矛盾、不合实际。
- **指令性幻觉**：不遵守用户指令。
- **上下文幻觉**：遗忘早期对话的内容。

### 1. 幻觉原因

- 模型核心是 Transformer 架构，大模型实际上是一个基于概率的生成器，推理时根据当前输入，生成概率最高的输出。本质上是基于统计意义的概率生成，而不是基于事实的逻辑推导。
- 大模型是通过海量数据训练，所以大模型的知识和能力受限于数据本身。
- 大模型的上下文窗口有限，会遗忘前文的内容。

### 2. 怎么解决幻觉

- RAG 增强：通过外置知识库增强大模型的知识。
- 提示词工程：引导大模型偏向实际内容，比如偏向 RAG 检索的内容。
- 模型微调：如果是专业领域大模型，使用领域数据集对大模型进行微调。

## (六) LLM 推理/规划能力

### 1. Chain of Thought（CoT 思维链）

- 思维链是一种**提示词工程**，通过 prompt 让大模型逐步推理问题并将推理过程输出，而不是直接给出结论，可以提高模型性能并让模型的输出具备可解释性。
- 思维链其实是 LLM 本身具备的能力，prompt 只是激活了该部分的能力。

#### 一、零样本思维链

- 直接在问题末尾加上一句 “让我们一步一步思考”，模型就会自动展开推理。
- 实现简单，但是不稳定。

#### 二、少样本思维链

- 在提示中给出几个“问题 → 推理步骤 → 答案”的完整范例，模型会模仿这种格式回答新问题。

### 2. Tree of Thoughts（ToT 思维树）

- 解决问题时，让模型在每一步都给出多个可能的路径，模型评估思路的合理性，选择最优路径继续推理，并允许回溯，直到找到最佳解决方案。

## (七) 参数 Temperature、Top-k、Top-p

1. **Temperature**

- Temperature 就是在对分数进行 **softmax** 之前，对所有分数除以温度值 t。
- Temperature < 1 就会使分布变尖锐，分数越高的候选项概率就越高，越容易被选取，模型越稳定。
- Temperature > 1 就会使分布变平坦，不同分数的候选项之间的概率差距变小，模型选分数低的候选项的概率变高了，模型的随机性就变大了。

2. **Top-k 和 Top-p**

- Top-k 只保留概率最高的k个候选，然后重新计算概率并采样。
- Top-p 就是从概率最高的候选项开始累加，当概率累加达到 p 时停止遍历，剩下的低概率长尾选项被丢弃。

## (八) MoE 混合专家架构（Mixture of Experts）

- 传统的稠密模型，每次输入所有的参数都参与计算。但是 MoE 架构内部拆成了多个专家子网络，每次只会激活其中一部分处理输入，其余参数不参与计算。
- MoE 使得用更低的成本获得更强的模型能力，让推理成本更加可控。

## (九) 强化学习

### 1. SFT 监督微调

- 用高质量的标注数据教模型"怎么说话"。主要做法是人工编写大量"一问一答"的对话范例，让机器学习这些数据集。

### 2. RLHF 基于人类反馈的强化学习

- 首先训练一个奖励模型，这个模型能够给回答打分，判断哪个回答更好。
- 然后用强化学习算法（如PPO）优化大模型，让模型生成的回答能够获得更高的奖励分数。

### 3. PPO 近端策略优化

- 限制策略更新的幅度，避免模型在一次更新中变化太大导致训练崩溃。
- **Actor** 模型：要训练的大模型。
- **Reference** 模型：初始状态的快照，防止模型偏离太远。
- **Reward** 模型：给回答打分。
- **Value** 模型：预测当前状态的预期得分。

### 4. DPO 直接偏好优化

- 对RLHF的简化。证明了可以直接用偏好数据优化策略，而不需要显式训练奖励模型。

# 二、RAG (**Retrieval-Augmented Generation 检索增强生成**)

## (一) 为什么要有RAG/RAG 能解决什么问题？

- **知识过期问题**：大模型只拥有训练数据截止日期之前的知识。
- **幻觉问题**：RAG 通过额外的知识提升回答质量、减少模型幻觉。
- **私有数据问题**：内部文档、私有数据无法被 LLM 直接访问。

1. **RAG 基本流程**

2. **离线阶段**

- 收集数据。
- 清洗数据：去除噪声、重复项和无关信息，确保数据的质量和准确性。
- 知识库构建：将数据按策略切块，如：固定大小、覆盖切片、语义分块等，然后用 Embedding 模型将片段转换为向量并存储在向量数据库中。

2. **检索**

- 将用户的问题转换为问题向量，并在向量数据库中检索，并选出最相关的 Topk 作为输入的一部分。

3. **增强**

- 将所有检索到内容进行重排，然后再选取最相关内容加入 Prompt 中，增强模型对特定问题的理解和回答。

4. **RAG 的缺点/难点**

- **数据质量**：因为 RAG 检索出的内容会直接影响到大模型的输入输出，那么 RAG 检索内容的质量直接取决于数据源的质量。
- **分块策略**：语义相关度、精确度，同一个系统文本复杂性，不同格式怎么分块。
- **多跳推理**：用户的回答往往综合多个文档、多个段落，那么如果检索错误，错误就可能沿着检索链条逐渐被放大。
- **系统性能**：系统复杂度提高，增加系统响应时间，检索环节可能成为系统性能瓶颈。

## (三) 文本分块 Chunking

- 一般存储到向量库中的记录至少包含 4 个部分：① 主键；② 原始文本；③ 向量；④ 元数据。

### 1. 为什么要分块

**① Embedding 模型的上下文窗口限制**。一整个文档太大，可能会超出上下文窗口，导致截断、成本显著增加。

**② 整个文档检索精度太差**。整个文档太长，语义太多、噪声太多，导致检索太准确，进而导致产生幻觉。

**③ 推理成本。**如果塞入整个文档，每次推理都要使用大量 token，造成使用成本上升和推理速度的下降。

**④ 支持增量更新。**分块更容易支持局部知识更新、版本管理等。

## (五) 向量数据库

- 向量数据库专门用来存储和检索高维向量的数据库。核心能力在于**近似最近邻搜索** (ANN，Approximate Nearest Neighbor) 以及 ANN 索引。

### 1. ANN 索引(Approximate Nearest Neighbor，近似最近邻搜索)

1. **分层可导航小世界图 HNSW**

- HNSW 核心是**分层图结构**，最高层稀疏图只包含若干个向量，最底层包含所有向量。
- 构建索引时，每个新的节点都会选择若干个近邻节点构成局部小世界图。

- **efConstruction** 建索引时的搜索宽度，**M** 每个向量在每层的最大连接数。

- 在每一层搜索时，维护一个大小 **ef** 的有序结果集，以及一个候选集，不断考察候选集中的节点的邻居是否能加入集合中，直到候选集不再更新。从最高层找到最底层，每一层用最终结果集中距离最小的点作为入口进入下一层。直到最底层，将最终候选集中前 **topk** 个节点作为结果返回。
- 优点：相同延迟下，能做到很高的召回率。
- 缺点：HNSW 需要存大量的图结构，因此对内存的要求比较高。

2. **倒排文件索引 IVF**

- 用聚类算法（如：K-Means）把所有向量分成 **nlist** 个簇，每个簇有一个中心点 (**centroid**)，代表这个簇里所有向量的"平均位置"。并维护一个倒排索引，记录该簇中所有原始索引。
- 查询时，先计算目标向量和所有簇中心点的距离，找到最近的 **nprobe** 个簇。然后在这 nprobe 个簇中进行暴力搜索。
- 优点：内存占用少。
- 缺点：精度较低，调参复杂。

3. **DiskANN**

- 基于磁盘的高性能图近邻搜索算法，将轻量级的索引结构置于内存中，将原始数据和索引存放在磁盘上。

### 2. Milvus

- **Collection**：数据组织的基本单位，相当于表。
- **Partition** 分区：Collection 内部的数据分区，相当于分区表。可以根据业务维度将数据分区，查询时指定分区，搜索范围更小。
- **Schema** 模式：定义了 Collection 每条数据包含的字段 (主键、向量、标量/元数据)，相当于表结构。
- **Index** 索引：**向量索引** ANN 用于加速向量相似度搜索，**标量索引**用于加速过滤条件执行。

## (六) 查询重写 Rewrite

- 在多轮对话中，用户当前提问可能存在上下文省略、表达口语化、语义混合等特点，直接使用当前输入查询知识库会导致严重**召回偏差**。结合历史对话用大模型对当前输入进行改写，得到语义完整的查询后再查知识库。

### 1. 基础重写

1. **代词/缩写补全**：把代词替换成它指代的具体实体，如果历史对话有多个实体选最近的实体。
2. **上下文补全**：补全历史对话中包含的信息。
3. **口语书面化**：将用户提问的口语改写成书面语，**不依赖对话历史**。
4. **多意图拆分**：用户一句话可能包含多个问题，拆分为子查询后分别检索，最后合并答案。

### 2. HyDE 假设文档嵌入

- 让 LLM 先根据问题生成一个“假设答案”，然后用这个假设答案在向量数据库中检索相似的真实文档，提高检索相关性。

### 3. 查询扩展

- 将关键词扩展得到近义词，提升关键词检索的召回率。
- 或者将原始问题改写得到若干个不同的版本，然后并行检索，最后将所有结果去重。

### 4. Step-back Prompting

- 将用户查询抽象成一个更贴近问题背景的问题，然后检索与这个背景相关的文档。

## (七) 意图识别与问题路由

### 1. 意图分类

- **知识检索**：知识库可以回答的问题。
- **工具调用**：用户查询的答案如果不属于知识库，则考虑查外部数据库、调 API 等。
- **闲聊对话**：用户在闲聊、打招呼等，不涉及具体的业务问题。
- **引导澄清**：用户问题过于模糊，系统无法判断意图或者无法给出答案，可以反问用户补充信息。

### 2. 意图识别方案

- **规则匹配**：关键词 + 正则表达式。
- **基于机器学习**：通过大量的意图识别的样本，对预训练的大模型进行微调。
- **大模型分类**：通过设计 Prompt 让大模型根据提供的意图类别描述来选择最合适的类别。
- **混合方案**：规则匹配只处理高置信度的、明确的场景；规则匹配没有处理的由大模型处理。

### 3. 问题路由

- 根据不同的意图判断是否需要调用工具、查询知识库或直接将原问题发送给大模型。

## (八) 混合检索

### 1. 关键词检索 — **BM25（Best Match 25）**

- BM25 是一种关键词检索的评分算法，衡量一个关键词在文档中有多重要。BM25 通常和倒排索引 (**关键词 -> 包含该关键词的文档列表**) 一起使用，BM25 依赖于倒排索引实现高效检索。
- **词频**（Term Frequency，TF）：`TF=关键词在文档中出现次数/文档总次数`，指关键词在某个文档中出现的频率。词频越大说明该文档和。
- **逆文档频率**（Inverse Document Frequency，IDF）：`IDF=log(总文档数/包含该关键词的文档数)`，反映关键词在整个文档集合中的稀缺性，平衡常见词和罕见词。
- **文档长度惩罚**：平衡长文档和短文档的优势。

### 2. 混合检索

- 同时执行向量检索和关键词检索，然后将两个结果融合 (如 RRF 算法) 得到最终排序。
- **RRF 倒数排名融合**

- RRF 只看排名不依赖分数。
- 对于一个分块，RRF 分数 = `RRF(d) = Σ 1 / (k + rank_i(d))`，其中， rank_i(d) 表示第 i 路检索中排名，k 表示平滑常数（默认 60）。

## (九) 重排序 Rerank

- 重排序模型一般使用 **Cross-Encoder**，把 query 和 chunk 拼接在一起输入 **Transformer** 模型，模型输出一个相关性分数，然后根据分数对候选段落进行排序。
- **粗排序** (Bi-Encoder)：两个文本独立编码，最后计算指标，比如：余弦相似度、欧氏距离等。速度快，用来召回、大规模相似性搜索。
- **精排序** (Cross-Encoder)：精度高但是慢，一半只对粗排结果进行精排序。

## (十) RAG 评价/量化

### 1. 检索阶段

- **命中率 Hit@k**：正确答案是否在召回的 Topk 分块中，是=1、否=0，总和求平均。不关注排名。
- **平均倒数排名 MRR**：没有正确答案=0，有正确答案=1/rank_i，总和求平均。关注正确答案的排名。
- **召回率 Recall@K** = Top-K 中相关内容数 / 知识库中所有相关内容总数
- **精确率** = Top-K 中相关内容数 / K

### 2. 生成阶段

- **忠诚度**：模型的输出是否忠实于检索到的 chunk 内容？是否是自己编造的内容？
- **答案相关性**：模型的输出是否回答了用户的问题？有没有答非所问？

### 3. 端到端/返回

- **答案正确率**：最终输出是否正确回答了用户问题？一般需要标准答案作为参考。
- **兜底率/空回答率**：当模型无法回答用户问题时触发兜底占总请求的比例。该指标和系统设定、知识库中的知识都有关系。
- **用户满意度**：用户显示反馈、系统隐式推断。
- **追问率**

### 4. LLM-as-Judge

- 用一个更强的大模型来充当评委，对另一个大模型的回答打分。
- 缺陷

- 位置偏差：倾向于对排在前面的答案给更高分。

## (十一) GraphRAG

- 使用**知识图谱**存储数据中的实体、关系及依赖。GraphRAG 使用图学习算法对数据进行语义聚合和层次化分析。
- 将输入切分为一系列文本单元，利用LLM创建对源数据中所有实体和关系的引用，然后使用这些引用来创建 LLM 生成的知识图谱。
- 通过图算法检测**社区结构**（进行创建自下而上的聚类），构建分层结构。使用 LLM 为每个社区生成**自然语言摘要**，帮助全面理解数据集。

### 1. 什么场景下需要使用图数据库/GraphRAG？

- GraphRAG 相比于传统 RAG 核心区别在于**多跳推理**。如果涉及到**多实体之间的关系推理**时可以考虑使用 GraphRAG。
- 典型：医疗场景、社区关系推理、供应链追溯等。

## (十二) Self-RAG 自反思 RAG

- Self-RAG 会用一个专门的模型判断提问是否需要查询外部知识，如果不需要则直接生成答案。
- 模型在生成答案的同时，会自我评估检索到的信息质量，并判断是否需要再次检索，解决了一次检索可能不够的问题。

## (十三) CRAG（Corrective RAG，纠正性检索增强生成）

- 当检索结果质量较差时，系统自动纠错。例如，触发补充检索，或启动知识图谱补全信息。

## (十四) 如何减少 RAG 场景下的幻觉？

### 1. RAG 中的幻觉

- 检索阶段没有召回相关内容，本质上是检索的问题，导致 LLM 因为不相关信息回答出错。
- LLM 没有严格遵守召回的文档，根据自己的预训练知识做出的回答。

### 2. 解决策略

- 对召回的文档进行**重排序**、**相关度过滤**等，排除不相关文档。
- 如果找不到相关分块，可以**拒绝回答**而不是给出错误结论。
- **Prompt 强约束**。
- 让 LLM 在输出中**引用**查询到的分块，**输出可追溯**。
